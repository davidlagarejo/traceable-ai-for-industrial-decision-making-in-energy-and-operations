# 0A_Legacy_1_4_to_0_8_Crosswalk
## Legacy 1–4 to Canonical 0–8 Crosswalk

## 1. Purpose

This document exists to prevent a destructive misunderstanding:

the legacy Phase 1–4 line is **not wrong** and must **not** be treated as failed work.

It is a strong architectural line built around a **workflow decomposition**:

1. public-data construction,
2. governed inference,
3. governed reporting,
4. verification bridge.

The canonical 0–8 constitution introduced later is built around a different decomposition:

1. observational constitution,
2. physical prior formation,
3. systemic structure,
4. operating-state structure,
5. M&V / verification path,
6. probabilistic finance,
7. computable normativity,
8. belief update,
9. TAD / decision admissibility.

These are not mutually exclusive architectures. They are different cuts through the same system.

The practical consequence is:

- the legacy line should be preserved;
- the new 0–8 line should govern future architecture;
- and migration must occur by **crosswalk and rebinding**, not by deletion and rewrite.

## 2. Governing preservation doctrine

The framework adopts the following preservation doctrine:

1. No legacy Phase 1–4 document is discarded merely because the canonical phase taxonomy changed.
2. No mature epistemic rule already closed in legacy documents may be silently lost.
3. Strong legacy material may be reclassified as:
   - a canonical phase component,
   - a transversal engine,
   - a shared motor,
   - or a reporting / governance layer.
4. Reporting and inference discipline do not disappear merely because they are no longer named as canonical phase numbers.
5. Migration must preserve:
   - traceability,
   - uncertainty discipline,
   - conflict preservation,
   - semantic ceiling,
   - and hardening / degradation logic.

## 3. Why the two architectures differ

The legacy 1–4 line decomposes the framework by **workflow stage**:

- gather and structure context,
- infer,
- report,
- harden.

The canonical 0–8 line decomposes the framework by **epistemic object class**:

- governance,
- physics,
- system structure,
- operations,
- verification,
- finance,
- regulation,
- cognition,
- decision.

The new line is therefore not a criticism of the old line. It is a broader constitutional re-cut designed to allow phases 5–8 to exist from the first report.

## 5. Detailed functional rebinding

### 5.1 Legacy Phase 1 — Public Data Engine

**What remains fully valuable**

- source admission discipline
- source-family governance
- anti-sprawl rules
- canonical schema discipline
- provenance and `SourceVersion`
- explicit assumptions
- visible uncertainty
- `facility_prior` logic

**How it rebinding maps**

- To canonical **Phase 0**:
  - source admission laws
  - anti-sprawl laws
  - provenance rules
  - semantic proportionality rules
  - computable gates and publication discipline

- To canonical **Phase 1**:
  - physically meaningful priors
  - climate, energy, and system plausibility
  - archetype-conditioned physical structure

- To canonical **Phase 2**:
  - facility anchor
  - system-family and asset-structure scaffolding
  - contextual object graph that later supports the twin

- To canonical **Phase 6**:
  - first-order regulatory applicability signals
  - jurisdiction bundle
  - regulatory trigger placeholders

**What should not happen**

- Do not say legacy Phase 1 was “only data.” It already contains serious epistemic governance.
- Do not throw the `facility_prior` away. It remains a core object.

### 5.2 Legacy Phase 2 — Decision Core

**What remains fully valuable**

- `Inference Case` as a governed atomic inferential unit
- anti benchmark -> diagnosis rule
- anti proxy -> truth rule
- anti hypothesis -> conclusion rule
- conflict preservation
- uncertainty preservation
- scoring limited to prioritization rather than truth
- validation requirement as mandatory field
- transformation and degradation logic

**How it rebinding maps**

- To canonical **Phase 1**:
  - physical hypotheses
  - mechanism plausibility logic

- To canonical **Phase 2**:
  - structural dependency hypotheses
  - subsystem interaction tensions

- To canonical **Phase 3**:
  - operating-state and regime hypotheses
  - operational tensions and actionability constraints

- To canonical **Phase 4**:
  - validation agenda
  - evidence gap logic
  - bridge-eligible claims

- To canonical **Phase 7**:
  - degradation rules
  - conflict preservation
  - anti-overassertion semantic control
  - explicit status transitions

- To canonical **Phase 8**:
  - prioritization logic
  - validation-first ordering
  - no-go logic under uncertainty

**What should not happen**

- Do not delete the Decision Core because canonical numbering changed.
- Do not collapse the old inferential discipline into “just TAD.”
- Do not let phases 1–3 in the new line become free-form because old Phase 2 already solved that governance problem.

### 5.3 Legacy Phase 3 — Reporting Engine

**What remains fully valuable**

- `Output Block`
- `Report Package`
- epistemic inheritance rules during rendering
- compaction discipline
- executive vs technical view logic
- circulation barrier
- sparse-case publication logic

**Canonical interpretation**

Legacy Phase 3 is not displaced by the canonical 0–8 line. It becomes a **transversal reporting and materialization architecture** that sits across all canonical phases.

In practical terms:

- canonical phases decide what may be claimed;
- legacy Phase 3 logic decides how those claims may be materialized, compacted, and circulated.

**What should not happen**

- Do not force Reporting Engine content into canonical Phase 8.
- Do not weaken reporting rules because reporting is “not a numbered phase anymore.”

### 5.4 Legacy Phase 4 — Verification Bridge

**What remains fully valuable**

- `claim_upgrade_candidate`
- `verification_pathway_register`
- `required_site_evidence_register`
- `baseline_hardening_register`
- `claim_upgrade_decision_map`
- `do_not_upgrade_register`
- explicit hold / degrade / block / upgrade logic

**How it rebinding maps**

- Primarily to canonical **Phase 4** as the core hardening architecture
- Operationally to canonical **Phase 7** because belief-state change depends on bridge outcomes
- Downstream to canonical **Phase 8** because TAD posture depends on whether claims stayed weak, held, blocked, or upgraded

**What should not happen**

- Do not reduce legacy Phase 4 to “just M&V later.”
- Do not drop its semantic outcome logic; it is one of the strongest parts of the framework.

## 6. What becomes canonical phase versus transversal engine

The key migration rule is this:

not every strong legacy phase should remain a canonical numbered phase in the new line.

### 6.1 Remains canonical as numbered-phase content

- public-data governance and prior logic -> absorbed into canonical Phase 0 and Phase 1
- inferential structure -> distributed into canonical Phases 1, 2, 3, 4, 7, 8
- verification bridge -> canonical Phase 4

### 6.2 Becomes transversal engine

- legacy Phase 3 Reporting Engine
- much of legacy Phase 2 semantic control

These become cross-cutting architectural engines rather than discarded content.

## 7. Migration without destruction

The correct migration sequence is:

1. Freeze the canonical constitution in Phase 0.
2. Preserve legacy 1–4 intact as lineage.
3. Add this crosswalk.
4. For each legacy artifact family, mark its canonical rebinding:
   - constitutional rule,
   - phase object,
   - transversal engine,
   - or future motor.
5. Only after the rebinding is explicit, rewrite or split documents if still necessary.

This avoids the failure mode of “cleaning up” the repo by destroying the best work inside it.

## 8. Practical doctrine for future Wiki architecture

For the Wiki architecture, this crosswalk has one major implication:

- the Wiki should not ingest the legacy 1–4 line as “obsolete.”
- it should ingest it as **high-value governed lineage** and tag each page by canonical role:
  - `canonical_phase`
  - `legacy_phase_lineage`
  - `transversal_engine`
  - `migration_bridge`

This will let the Wiki preserve both:

- the strong old workflow architecture,
- and the new constitutional 0–8 architecture.

## 9. Final rule

The correct interpretation of the repo after the constitutional rewrite is:

the framework now has a canonical 0–8 constitution, but the old 1–4 work remains authoritative lineage material wherever it does not conflict with Phase 0 and wherever it can be rebound into the new architecture.

Therefore:

- the old work is not invalidated;
- the new work is not ornamental;
- and future restructuring must proceed by explicit crosswalk, not by epistemic amputation.
