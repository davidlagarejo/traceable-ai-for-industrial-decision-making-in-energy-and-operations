## Principle

> **AI builds the machinery. The framework generates the intelligence.**

If Claude (AI assistant) writes patterns / combinations / hypotheses / justifications / source curations by hand, the framework stops being an autonomous industrial brain and becomes a proxy for Claude's hardcoded content.

This registry lists **everything Claude introduced into the codebase that should have been generated by the framework itself**. Each item is **scaffolding** — it works today, it preserves regression 7/7, but it must be progressively replaced by V4 framework intelligence (Industrial Research Engine).

## Rules

1. **No new entries.** Claude must not add new patterns, combinations, hybrids, justifications, source curations, or per-family content branches. If you find yourself about to hardcode domain knowledge, **stop**.
2. **No expansion of existing entries.** Each item below is FROZEN at its current size. Don't add an 8th cold-chain pattern, a 6th hybrid, a 145th source, etc.
3. **Reach via framework only.** When V4 generators produce equivalent or better content, **delete the corresponding scaffolding item from this registry** and from the codebase.
4. **Headers in files.** Each scaffolded file carries a header comment pointing to this registry. If the header is missing, the file should not have content written by Claude.

## Provenance verification method

Every item was verified via `git log --oneline --diff-filter=A -- <path>`. Items with origin commits authored by Claude (`recovery(v2): ...`, `recovery(v2-live): ...`, `recovery(v2-critical): ...`) are scaffolding. Items pre-existing the recovery (e.g. commit `810844d feat(zlab_skill): autonomous research loop infrastructure`) are user content and **not in this registry**.
