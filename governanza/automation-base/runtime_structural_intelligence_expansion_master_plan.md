# Runtime Structural Intelligence Expansion — Master Plan

## Objective

Expand ZLab from a pure `decision gating` framework into a `structural-intelligence` framework without breaking:

- current anti-hallucination discipline
- current public-data routing and asset-context hardening
- current claim gating
- current TAD graduation
- current system-consistency blocking before PDF

The target evolution is:

`data -> system abstraction -> dominant variables -> cross-layer contradictions -> problem reframing -> conditional redesign -> financial exposure -> TAD`

Not by replacing the existing stack, but by **adding a structural-intelligence lane** that later becomes authoritative where evidence supports it.

---

## 1. Non-Breaking Architecture Principle

Do **not** rewrite the current pipeline around a new monolith.

Do this instead:

1. keep the existing `identity / routing / canonical field / maturity / claims / report-type / TAD / render / validator` chain intact;
2. add new structural-intelligence motors downstream of canonical context;
3. let the new lane enrich the current decision core before it is allowed to dominate it;
4. make `motor_036` the final hard gate for contradictions between the old and new lanes.

This avoids breaking:

- `motor_007` early target gating
- `motor_012` canonical field reconciliation
- `motor_034` maturity and claim permissions
- `motor_033` TAD sovereignty
- `motor_036` consistency blocking
- `motor_016/017` governed report assembly/render

## 4. Engine Map: Purpose, Inputs, Outputs, Claims, Limits, Tests

## 4.1 `motor_037` — System Abstraction Engine

### Purpose

Build a minimum structural abstraction of the asset/system without pretending to know the full process.

### Inputs

- `motor_012.asset_field_register`
- `motor_012.canonical_asset_context_summary`
- `motor_028.source_register`
- `motor_034.cluster_maturity_register`
- `motor_039.archetype_resolution`
- target definition / jurisdiction / asset type

### Outputs

`system_abstraction`

```json
{
  "asset_type": {},
  "business_function": {},
  "value_creation_mechanism": {},
  "dominant_process_type": {},
  "dominant_physical_drivers": [],
  "dominant_operational_drivers": [],
  "control_structure": {},
  "constraint_structure": {},
  "economic_driver": {},
  "regulatory_exposure": {},
  "evidence_maturity": {}
}
```

Each field must carry:

- `statement`
- `evidence_state`
- `supporting_sources`
- `falsification_condition`
- `minimum_evidence_required`

### May assert

- minimal structural hypotheses labeled as `ARCHETYPAL_PRIOR` or `CONDITIONAL_HYPOTHESIS`
- observed structural facts when directly supported

### May not assert

- full process truth
- specific savings logic
- asset behavior closure

### Anti-hallucination rules

- never promote `ARCHETYPAL_PRIOR` to `OBSERVED_FACT`
- if no field/source support exists, emit `not_observed`

### Tests

- manufacturing laminate seed resolves thermal/resin/curing as `ARCHETYPAL_PRIOR`, not `OBSERVED_FACT`
- One Vanderbilt resolves central plant / tenant load / LL97 exposure as conditional/observed mix depending on public evidence

## 6. Anti-Hallucination Rules

1. No `ARCHETYPAL_PRIOR` may be rendered as `OBSERVED_FACT`.
2. Every structural statement must carry `evidence_state`.
3. Every hypothesis must carry:
   - validity condition
   - falsification condition
   - minimum evidence required
4. Every scenario must carry:
   - financial meaning
   - evidence needed
   - falsification condition
5. Every redesign path must be conditional.
6. Every peer comparison must carry evidence state.
7. Every TAD action must be checked against claim permission.
8. No digital twin recommendation without dominant-variable maturity.
9. No technology-first recommendation without problem-framing support.
10. If the problem is premature or misframed, the system must be allowed to say so.

## 13. Technical Risks

1. **Motor sprawl**
   - too many new adapters without shared schemas
2. **Dual-truth drift**
   - current lane and new lane diverge if not reconciled through `motor_036`
3. **Template regression**
   - new sections leak placeholders or archetypal language as fact
4. **Peer-comparison hallucination**
   - public peer evidence is usually weaker than local asset evidence
5. **Overeager redesign output**
   - system starts “recommending” instead of conditionally hypothesizing
6. **Output mode explosion**
   - too many modes with weak activation rules create confusion
7. **DAG instability**
   - inserting new motors too early can break current gating/reporting behavior

### Mitigation

- phase-gate the new lane
- internal artifacts first
- keep claim gating sovereign
- let `motor_036` arbitrate contradictions
- certify on known cases before broad rollout
