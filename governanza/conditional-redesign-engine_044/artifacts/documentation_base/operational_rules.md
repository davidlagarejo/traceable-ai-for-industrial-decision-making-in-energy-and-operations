# Operational Rules — Conditional Redesign Engine

Motor ID: motor_044

## sequencing
1. leer variables dominantes y conflicto;
2. leer problem framing;
3. leer comparación bounded;
4. formular hipótesis de rediseño sólo si existe una dirección plausible y falsable;
5. anexar evidence_needed, kill_condition y next_evidence.

## evidence_rules
- si la hipótesis fuente es condicional, el rediseño también debe ser condicional;
- `next_evidence` no puede ser una lista genérica sin relación con el conflicto;
- `economic_logic` debe explicar por qué el rediseño importa, no cuánto retorno promete.

## boundary_rules
- no emitir recomendación final;
- no cerrar economics;
- no borrar el camino de falsificación;
- no presentar rediseño como peer superiority claim.
