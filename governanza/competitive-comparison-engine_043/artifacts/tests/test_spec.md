# Test Spec — Competitive Comparison Engine

Motor ID: motor_043

## happy_path
- Building: emitir comparación condicional con submetering, green-lease o BMS discipline.
- Manufacturing: emitir comparación con process-map maturity, thermal integration o uptime framing.

## sparse_case
- Si no hay peer puntual observado, el motor puede caer a `archetypal_best_practice` conservando límites explícitos.

## malformed_input
- Sin benchmark estructural o sin arquetipo, el motor no debe fabricar comparación fuerte.

## edge_cases
- `comparison_mode` puede variar por familia y evidencia.
- `what_it_does_not_prove` es obligatorio incluso cuando la fila sea muy convincente.

## pass_criteria
- Cada fila tiene ventaja estructural y límites.
- `evidence_state` es válido.
- `competitive_comparison_count` coincide con el register.
- Building y manufacturing producen contenidos distintos.

## fail_criteria
- comparación genérica;
- peer drift entre familias;
- desaparición de transferability o source_reference;
- count desincronizado.
