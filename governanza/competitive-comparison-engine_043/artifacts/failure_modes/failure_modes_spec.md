# Failure Modes Spec — Competitive Comparison Engine

Motor ID: motor_043

## failure_modes_list
- `PROOF_BY_COMPARISON`: la comparación se presenta como prueba final.
- `ARACHETYPE_BLUR`: el peer ya no pertenece al arquetipo correcto.
- `TRANSFERABILITY_HOLLOW`: aparece ventaja pero no queda claro si migra o no.
- `BEST_PRACTICE_SLOP`: la fila parece texto genérico de consultoría.

## anti_patterns
- copiar prácticas “de referencia” sin ligarlas al benchmark;
- hablar de competidor superior sin explicar el porqué físico u operacional;
- usar comparación para justificar CAPEX.

## degradation_signals
- filas intercambiables entre building y manufacturing;
- no aparece `what_it_does_not_prove`;
- todos los peers son vagos o sin referencia.

## expensive_errors
- sesgar rediseño o tesis ejecutiva;
- impulsar claims comparativos prematuros;
- sobreestimar transferabilidad de una práctica.
