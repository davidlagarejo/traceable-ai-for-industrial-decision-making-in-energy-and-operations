# Master Concept Doc — Problem Framing Engine

Motor ID: motor_041

## core_job

`motor_041` convierte conflicto estructural y señales de comparación inválida en una formulación de problema que sí puede investigarse sin sesgar estrategia, CAPEX o claims demasiado pronto.

No responde “qué hacer”. Responde “qué problema real debe probarse”.

## why_it_exists

En esta capa el framework ya tiene:

- arquetipo;
- abstracción del sistema;
- variables dominantes;
- conflictos cross-layer;
- y, en algunos casos, señales de congruencia que muestran que el framing original era inválido.

Sin una etapa explícita de problem framing, downstream puede heredar el síntoma equivocado:

- “alto consumo por área”;
- “el retrofit debe capturar ahorro owner”;
- “el problema es mantenimiento”;
- “el peer benchmark ya prueba ineficiencia”.

`motor_041` obliga a reformular ese síntoma como hipótesis investigable y bounded.

## behavioral_contract

- Building: debe reencuadrar alrededor de control boundary, exposición regulatoria y separación owner-vs-tenant.
- Manufacturing: debe reencuadrar alrededor de carga estructural de proceso, uptime y mantenimiento.
- Logistics fallback: si el framing estructural queda vacío o inadmisible, puede traducir el invalid problem frame de `motor_051`.

## non_goals

- no propone solución final;
- no compara peers;
- no calcula economía final;
- no abre claims como si el problema ya estuviera demostrado;
- no reemplaza la evidencia necesaria por redacción persuasiva.
