# Cases Index

Each case gets its own workspace.

Use [`_case-template/`](./_case-template/) as the starting pattern.

Default case construction should follow the initial product promise, not canonical phase order.

## Minimum case logic

Every case should be able to answer:

- what asset or asset set is in scope
- what is not understood yet
- what decisions are exposed
- what tensions dominate
- what to verify next
- what the financial and regulatory posture is
- how beliefs changed
- what TAD currently supports

## Default case spine

The preferred first-pass case spine is:

1. case overview
2. what is misunderstood
3. decisions at risk
4. fragile assumptions
5. what not to do yet
6. what to verify first
7. preliminary financial exposure
8. distance to verification-grade
9. touchpoints and deliverables

This is the primary front-of-product reading order inside the wiki.
