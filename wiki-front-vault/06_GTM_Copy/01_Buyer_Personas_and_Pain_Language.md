# Buyer Personas and Pain Language

## Real buyer pain

The initial buyers usually do not say:

- "I need more AI"
- "I need a better dashboard"

They say:

- this took too long
- this does not scale
- I cannot defend this number
- this depends too much on one expert
- the committee will not trust this
- the bank will not accept this risk
- we spent weeks on the wrong problem

## Rule for GTM pages

GTM pages should speak in that pain language.

They should not default to:

- generic efficiency language
- commodity ESG language
- generic AI hype language

## Buyer clusters

### Capital allocators

Typical concern:

- can this number survive committee scrutiny
- can this case survive lender scrutiny
- is deeper diligence justified

### Diligence and technical sponsors

Typical concern:

- what is actually weak in the case
- what assumption is carrying too much weight
- what should be checked before more capital or time is committed

### ESCOs and structured project developers

Typical concern:

- which opportunities are not mature enough to pitch yet
- where the case may collapse later
- what to verify before a project is overcommitted

## Copy implication

The copy should make the buyer feel:

- this system sees where the case is weak
- this system reduces wasted diligence
- this system improves defendability before heavier work

It should not make the buyer feel:

- this is another dashboard
- this is generic efficiency software
- this is an AI wrapper around benchmarking
